# BRIEF — «SANA»: AI-аналитик внутри BI (заказчик Kaz-analytics)

## §1. Заказчик и боль
Kaz-analytics (сфера заказчика — автомобильная промышленность; ответственный — Керейбайев Нуриман).
Боль: компании вложились в BI, но пользу извлекает узкий круг аналитиков. Бизнес-пользователь
видит графики, но за ответом на конкретный вопрос идёт к аналитику и ждёт выгрузку. Нужен
«встроенный в BI AI-аналитик»: вопрос на естественном языке → готовый ответ. Дедлайн приёма
решений: **13.07.2026 включительно**. Вознаграждение договорное; заказчик открыт к пилоту —
значит, продаём не хакатонную поделку, а **продукт, готовый к пилоту**.

## §2. Концепт: SANA (каз. «сана» — сознание, разум)
Слоган: **«Спросите свои данные»**. Позиционирование: *не чат-бот рядом с BI, а доверенный
аналитик внутри неё*. Ключевая архитектурная идея (наш аналог schema-driven из прошлой победы):
**Semantic Layer как источник истины**. Метрики, измерения, join'ы и права описаны декларативно;
LLM переводит вопрос в строгий JSON-план по этому слою; наш компилятор собирает SQL из
whitelist-фрагментов; расчёт делает база; LLM лишь формулирует вывод из уже посчитанных чисел.
Формула питча: **«AI понимает вопрос — считает база — человек видит, как посчитано»**.
Это закрывает главный страх заказчика (галлюцинации) архитектурно, а не обещанием.

## §3. Семь требований ТЗ = наш чек-лист оценки (каждое — с доказательством на стенде)
| # | Требование ТЗ | Чем доказываем |
|---|---|---|
| 1 | Диалог на естественном языке внутри дашборда | Ask-панель в воркспейсе + embed-виджет в «чужой» BI |
| 2 | Ответы на фактических данных, не «угадывание» | Semantic Layer → JSON-план → компилятор SQL; панель «Как посчитано» (план → SQL → строк обработано → определения метрик) |
| 3 | Автопостроение визуализаций | Детерминированный выбор типа графика по форме результата (тренд→line, топ-N→bar, доля→donut, одно число→KPI-карта) + таблица всегда |
| 4 | Готовое аналитическое заключение | Блок «Вывод»: 2–4 предложения + буллеты, дельты посчитаны детерминированно, LLM только формулирует |
| 5 | Отраслевая настраиваемость | 3 отраслевых пака (авто — основной, ритейл, банк) на одном ядре; переключатель отрасли; docs «новый пак за 30 минут» |
| 6 | Встраивание поверх существующей BI | Страница /legacy-bi — «существующий корпоративный дашборд», поверх которого живёт виджет SANA; сниппет подключения в 1 строку; /embed режим |
| 7 | Безопасность корпоративного уровня | RBAC: роли со scope (CEO видит всё, директор региона — только свой регион — тот же вопрос, разные данные); AuditLog запросов; LLM не видит сырые строки данных (только план и агрегаты); данные в контуре (self-host ready), AI-адаптер on-prem-ready |

## §4. Отраслевые паки (данные в Turso, сид генерируется)
- **AUTO (основной — отрасль заказчика!):** дилеры (12, по регионам РК), модели (20: 4 бренда ×
  сегменты), продажи 24 мес (~45 000 строк: дата, дилер, модель, кол-во, выручка ₸, скидка %,
  канал, менеджер), остатки на складах, сервисные заказы с NPS. Встроенные аномалии: провал
  продаж одного дилера в мар.2026, всплеск скидок по одному бренду — пища для авто-инсайтов.
- **RETAIL:** магазины, категории, продажи, возвраты (~20 000 строк).
- **BANK:** филиалы, продукты (депозиты/кредиты), выдачи/остатки (~10 000 строк).
Все суммы в ₸, даты 2024-07…2026-06, реалистичная сезонность.

## §6. WOW-пакет (изолированно, после ядра)
W1 **Панель доверия «Как посчитано»** (план→SQL→метрики→строки) — enterprise-нокаут.
W2 **Embed поверх «чужой» BI** (/legacy-bi) + сниппет «1 строка кода».
W3 **Авто-инсайты**: «SANA заметила: 3 аномалии за период» (z-score детерминированно, LLM формулирует) — проактивная карточка на витрине.
W4 **Вопрос на казахском** → корректный ответ (просто работает через LLM; 6-8 казахских вопросов в подсказках).
W5 **Экспорт ответа**: карточка PNG/PDF (график+вывод+подпись «посчитано SANA») для отправки руководителю.
W6 **Демо-тур** для эксперта (паттерн прошлого проекта) + follow-up-подсказки после каждого ответа («Почему упало? → разложить по дилерам»).

## §7. ДЕМО-СЦЕНАРИЙ (по нему — prod-verify и приёмка)
1. Гость открывает `/`: за 5 секунд ясно, что это; живые цифры (не нули); кнопка «Попробовать демо».
2. /login: один клик «Войти как CEO» → воркспейс с паком AUTO.
3. Печатает «Какая выручка по месяцам за последний год?» → line-график + KPI + «Вывод» с
   дельтами → раскрывает «Как посчитано»: план, SQL, 45 210 строк, определение метрики.
4. «Топ-5 дилеров по продажам в 2026» → bar + вывод; кликает follow-up «Разложить по моделям».
5. Спрашивает на казахском («Өткен айдағы ең көп сатылған модель қандай?») → корректный ответ.
6. Выходит, «Войти как директор региона» → тот же вопрос про топ дилеров → данные только по
   Алматы, плашка «ваш доступ ограничен регионом» — RBAC вживую.
7. Переключает пак на RETAIL → те же вопросы работают на другой отрасли (настраиваемость).
8. Открывает /legacy-bi: «старый корпоративный дашборд» + плавающий виджет SANA поверх →
   задаёт вопрос прямо там; рядом сниппет подключения в 1 строку.
9. На витрине — карточка «Авто-инсайты»: 3 находки с графиками-миниатюрами.
10. Экспортирует ответ карточкой PNG.
